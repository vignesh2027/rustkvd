Deep Dive

System Architecture

Three-node cluster with gRPC ingress, Raft consensus, LSM storage, and a consistent hash ring for data placement.

What's inside

Built for production

Every component is designed for correctness, performance, and operational simplicity.

Raft Consensus
Leader election in <5ms. Log replication with quorum writes. InstallSnapshot for lagging followers. Linearizable reads via committed log index.
LSM Storage Engine
WAL with CRC32 checksums + fsync. MemTable backed by BTreeMap. Bloom-filtered SSTables for fast negative lookups. Background compaction thread.
Consistent Hashing
150 virtual nodes per physical node. SHA-256 key placement. Replication factor 3. Automatic rebalancing on node join/leave with minimal data movement.
MVCC
Every write gets a monotonic u64 version stamp. Snapshot reads at any past version. Garbage collect old versions below the global watermark.
gRPC API
Get, Put, Delete, Scan, streaming Watch, NodeStatus. Built on Tonic + Prost. Automatic redirect on NotLeader error. Bidirectional streaming Watch events.
Zero GC — Rust Ownership
No garbage collector, no stop-the-world pauses, no data races. Rust's ownership model guarantees memory and concurrency safety at compile time.

Under the hood

How Raft Works

Raft is a consensus algorithm designed for understandability. Here's how it guarantees consistency across the cluster.

1
Leader Election
When a follower's election timer fires without hearing from a leader, it increments its term and becomes a candidate. It sends RequestVote RPCs to all peers. If it receives votes from a majority of nodes, it becomes the new leader and immediately sends heartbeat AppendEntries to assert authority.
election_timeout: 150–300ms heartbeat_interval: 50ms quorum = ⌊N/2⌋ + 1
2
Log Replication
All writes go to the leader. The leader appends the entry to its log, then sends AppendEntries RPCs to all followers in parallel. Once a majority acknowledges the entry, the leader commits it (advances commit_index) and applies it to the state machine. The response is sent to the client only after commit.
write → leader log parallel replication quorum ACK → commit apply → LSM
3
Safety Guarantees
Raft guarantees: Log Matching — if two logs have an entry with the same index and term, all preceding entries are identical. Leader Completeness — a leader always has all committed entries. State Machine Safety — all nodes apply the same log entries in the same order, guaranteeing linearizability.
log matching leader completeness linearizability

Developer API

Simple, ergonomic client

The Rust client library is async-first, built on Tokio. Three lines to read, write, or stream.

use rustkvd_client::Client;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = Client::connect("http://localhost:7001").await?;

    // Put — returns the MVCC version assigned to this write
    let version = client
        .put("user:1001", b"Alice".to_vec(), None)
        .await?;

    println!("Written at version {}", version);
    // Output: Written at version 42

    Ok(())
}
use rustkvd_client::Client;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = Client::connect("http://localhost:7001").await?;

    // Get — optionally pass a version for snapshot reads
    let value = client.get("user:1001", None).await?;

    match value {
        Some(bytes) => println!("{}", String::from_utf8_lossy(&bytes)),
        None        => println!("key not found"),
    }
    // Output: Alice

    // Snapshot read at a past version
    let old = client.get("user:1001", Some(40)).await?;
    println!("At v40: {:?}", old);

    Ok(())
}
use rustkvd_client::{Client, EventType};
use futures::StreamExt;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = Client::connect("http://localhost:7001").await?;

    // Watch — streaming gRPC; receive all events under prefix
    let mut stream = client.watch("user:").await?;

    println!("Watching user: prefix...");
    while let Some(event) = stream.next().await {
        let event = event?;
        match event.event_type {
            EventType::Put    => println!("PUT  {}: {:?}", event.key, event.value),
            EventType::Delete => println!("DEL  {}", event.key),
        }
    }

    Ok(())
}

Get running in minutes

Quick Start

Spin up a 3-node local cluster in three commands.

Step 1 — Clone & build
$git clone https://github.com/vignesh2027/rustkvd && cd rustkvd
$cargo build --release
Compiling rustkvd v0.1.0 ... Finished release [optimized] target(s)
Step 2 — Start 3 nodes (3 terminals)
# terminal 1
$./target/release/rustkvd --id node1 --addr 127.0.0.1:7001 \
--peers 127.0.0.1:7002,127.0.0.1:7003
# terminal 2
$./target/release/rustkvd --id node2 --addr 127.0.0.1:7002 \
--peers 127.0.0.1:7001,127.0.0.1:7003
# terminal 3
$./target/release/rustkvd --id node3 --addr 127.0.0.1:7003 \
--peers 127.0.0.1:7001,127.0.0.1:7002
Step 3 — Try it out
$./target/release/rustkvd-cli --peers localhost:7001 put hello world
OK (version: 1)
$./target/release/rustkvd-cli --peers localhost:7001 get hello
world
$./target/release/rustkvd-cli --peers localhost:7001 status
Node: node1 | Role: leader | Term: 1
